# Gothic Forge - API Template

A REST API-only template with no frontend, optimized for backend services and microservices.

## What's Included

- ✅ RESTful routing structure
- ✅ JSON request/response handling
- ✅ API versioning (/v1/, /v2/)
- ✅ Request validation
- ✅ API key authentication
- ✅ JWT token authentication
- ✅ Rate limiting per API key
- ✅ OpenAPI/Swagger documentation
- ✅ CORS configuration
- ✅ Database integration
- ✅ Structured logging
- ✅ Error handling with standard codes
- ❌ No frontend templates
- ❌ No HTML rendering

## Quick Start

```bash
# Install dependencies
gforge install

# Run migrations
gforge db --migrate

# Start development server
gforge dev

# Test API
curl http://localhost:8080/api/v1/health
```

## Database Schema

### API Keys Table

```sql
CREATE TABLE api_keys (
    id SERIAL PRIMARY KEY,
    key VARCHAR(64) UNIQUE NOT NULL,
    name VARCHAR(255) NOT NULL,
    user_id INTEGER,
    rate_limit INTEGER DEFAULT 1000,
    expires_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_used_at TIMESTAMP
);
```

## Available Endpoints

### API v1

#### Health & Status
- `GET /api/v1/health` - Health check
- `GET /api/v1/status` - API status and version

#### Authentication
- `POST /api/v1/auth/login` - Login (returns JWT)
- `POST /api/v1/auth/refresh` - Refresh JWT token
- `POST /api/v1/auth/apikey` - Generate API key

#### Resources (Example CRUD)
- `GET /api/v1/resources` - List resources
- `GET /api/v1/resources/:id` - Get resource
- `POST /api/v1/resources` - Create resource
- `PUT /api/v1/resources/:id` - Update resource
- `DELETE /api/v1/resources/:id` - Delete resource

### API v2 (Future)

- `GET /api/v2/...` - Version 2 endpoints

### Documentation
- `GET /docs` - Swagger UI
- `GET /docs/openapi.yaml` - OpenAPI specification

## Authentication

### API Key Authentication

Include API key in header:

```bash
curl -H "X-API-Key: your-api-key" \
  http://localhost:8080/api/v1/resources
```

### JWT Authentication

1. Login to get token:

```bash
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"password"}'
```

2. Use token in requests:

```bash
curl -H "Authorization: Bearer your-jwt-token" \
  http://localhost:8080/api/v1/resources
```

## Request/Response Format

### Success Response

```json
{
  "success": true,
  "data": {
    "id": 1,
    "name": "Example"
  },
  "meta": {
    "timestamp": "2024-01-01T00:00:00Z"
  }

```

### Error Response

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid request parameters",
    "details": {
      "field": "email",
      "issue": "Invalid email format"
    }
  },
  "meta": {
    "timestamp": "2024-01-01T00:00:00Z"
  }
}
```

## Rate Limiting

Rate limits are enforced per API key:

- Default: 1000 requests per hour
- Configurable per API key in database
- Returns `429 Too Many Requests` when exceeded

Headers included in response:
```
X-RateLimit-Limit: 1000
X-RateLimit-Remaining: 999
X-RateLimit-Reset: 1640995200
```

## API Versioning

The API supports multiple versions:

- `/api/v1/` - Current stable version
- `/api/v2/` - Next version (beta)

Clients should always specify version in URL.

## Deployment

### Deploy to Production

```bash
# Set up database provider
gforge secrets --set COCKROACH_API_KEY=<your-key>

# Deploy
gforge deploy --live
```

### Docker Deployment

```bash
# Build image
docker build -t my-api .

# Run container
docker run -p 8080:8080 \
  -e DATABASE_URL=postgresql://... \
  -e JWT_SECRET=... \
  my-api
```

## Security

### Best Practices

1. **Always use HTTPS in production**
2. **Rotate API keys regularly**
3. **Set appropriate rate limits**
4. **Validate all input**
5. **Use JWT with short expiration**
6. **Enable CORS only for trusted origins**
7. **Log security events**

### API Key Generation

```bash
# Generate new API key
curl -X POST http://localhost:8080/api/v1/auth/apikey \
  -H "Authorization: Bearer admin-jwt" \
  -H "Content-Type: application/json" \
  -d '{"name":"Mobile App","rate_limit":5000}'
```

## Customization

### Add New Endpoints

1. Add handler in `internal/api/v1/handlers.go`
2. Register route in `internal/api/v1/routes.go`
3. Update OpenAPI spec in `docs/openapi.yaml`
4. Add tests

### Add New Version

1. Copy `internal/api/v1/` to `internal/api/v2/`
2. Update handlers and routes
3. Register in main router
4. Update documentation
